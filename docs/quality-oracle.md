# Composite benchmark quality oracles

ModelSkyline recommends keeping benchmark scores on separate frontiers. A
SWE-bench score, an ARC-AGI score, and a tool-use score describe different
workloads, cohorts, harnesses, and units; averaging their leaderboard numbers
directly would manufacture comparability.

`QualityOraclePolicy` is the explicit opt-in alternative for an operator who
needs one quality axis. It defines an operator-authored index for a new,
versioned composite workload. It is not a learned universal model-quality
score and does not replace `QualityBundlePolicy`.

## Trust and replay boundary

The pipeline is deliberately layered:

```text
benchmark capture
  -> route-free QualityEvidenceSet
  -> reviewed reconciliation to complete OfferingKey values
  -> workload-specific observations and frontier snapshots
  -> QualityBundleSnapshot coverage matrix
  -> optional QualityOracleSnapshot scalar index
  -> verified ObservationCatalog quality signal
```

The oracle never sees or matches leaderboard display names. It receives only
the complete `OfferingKey` values already reconciled by upstream layers. Those
keys include provider, endpoint, region, service tier, quantization, reasoning
setting, and harness where applicable. `offering_id` and complete keys must
both be unique.

A snapshot SHA-256 detects mutation; it does not authenticate an artifact.
Every public catalog consumer therefore requires all four trust inputs and
performs deterministic replay:

```python
quality_oracle_catalog(policy, bundle, snapshot, now=now)
enrich_catalog_with_quality_oracle(catalog, policy, bundle, snapshot, now=now)
```

There is no public unchecked snapshot-to-catalog path. Consumption rejects an
expired snapshot, an excessively future-dated snapshot or source capture, a
different policy, and a different exact bundle.

The bundle itself should first be replay-verified against its exact component
frontiers with `verify_quality_bundle_snapshot` when those inputs are
available.

Component frontiers must be generated by v0.8 or later and carry their
self-hashed axis-evidence inventory. The inventory is bound to the exact config,
catalog, workload, axis descriptors, timestamp, and complete `OfferingKey`
universe. Both axes are attempted independently. Bundle construction reads the
selected quality estimate from this inventory even if missing or stale cost,
latency, or another companion metric rejected the route from `evaluated`; it
never reconstructs evidence from a rejection message.

## Stable policy versus exact capture

The policy contains only stable semantics and governance choices:

- bundle ID and semantic version;
- exact component IDs, workload/cohort references, and selected quality axes;
- typed source semantics: ID, version, public URL, and methodology;
- typed fixed normalization references;
- Decimal weights, correlation groups, and operator rationales.

It deliberately excludes bundle policy hashes, bundle and frontier snapshot
hashes, catalog/configuration hashes, retrieval timestamps, raw capture hashes,
and rights metadata. Those exact replay and audit bindings live in each
`QualityOracleSnapshot.component_captures` entry. Thus a new price catalog or
other companion-axis change does not force a new semantic oracle policy.

The snapshot stores the exact bundle policy and snapshot hashes, bundle
generation and expiry times, every exact `QualityBundleComponent`, complete
component `SourceReference` records, and separate source identity domains:

- semantic identity: ID, version, URL, and methodology;
- raw identity: source ID and raw artifact SHA-256;
- retrieval identity: source ID and retrieval timestamp;
- rights identity: source ID, license, and terms URL;
- capture identity: the complete source descriptors.

Changing retrieval or rights state therefore changes the snapshot without
silently changing the semantic policy. Source tuples are canonicalized, so a
mere tuple-order change is equivalent. Two components that use the same raw
artifact SHA-256 must declare the same correlation group, even if the source
records use different IDs.

Source retrieval timestamps may not exceed oracle generation time by more than
the configured `max_clock_skew` (five minutes by default). Build and replay use
the same bound.

## Selected-quality projection

Each snapshot contains domain-versioned component and aggregate
`selected_quality_projection_sha256` values. A component projection contains
only:

- component ID, exact benchmark workload, and selected quality-axis descriptor;
- the canonically ordered complete `OfferingKey` universe;
- each candidate's measured, missing, or quarantined state;
- the selected quality `AxisEstimate` and stable source semantics when measured;
- quarantine reason codes when quarantined.

It excludes the companion frontier axis, Pareto membership and order, frontier
and catalog/configuration hashes, bundle policy hash, and generation/expiry
times. It also excludes raw artifact hashes, retrieval timestamps, licenses,
and terms URLs. Those audit and rights fields still bind the exact snapshot,
but changing one does not falsely claim that the selected quality measurement
changed. Consequences are intentional:

| Change | Semantic policy | Selected-quality projection | Exact oracle snapshot |
|---|---:|---:|---:|
| Price or other companion-axis value | stable | stable | changes |
| Companion-axis availability or freshness only | stable | stable | changes |
| Frontier/catalog/time pin only | stable | stable | changes |
| Selected quality value or bounds | stable | changes | changes |
| Candidate status or quarantine reason | stable | changes | changes |
| Raw capture, rights, or retrieval only | stable | stable | changes |
| Complete `OfferingKey` | stable | changes | changes |
| Source ID/version/URL/methodology | changes | changes or becomes incompatible | changes |
| Workload or selected axis | changes | changes or becomes incompatible | changes |
| Weights or normalization only | changes | stable | changes |

A newly built exact snapshot changes for a price update because replay binds
the precise bundle used. The prior snapshot is not retroactively invalidated:
it remains valid against its original bundle until expiry. The projection hash
lets caches and operators see that the selected quality evidence itself did not
change.

## Typed normalization and Decimal aggregation

The v1alpha1 algorithm supports only a typed, self-hashed fixed min-max
reference. `build_fixed_min_max_normalization` derives
`reference_sha256` from every normative field: schema and algorithm identity,
reference ID/version, unit, anchors, out-of-reference behavior, and rationale.
Loading rejects a digest copied from another scale or any field mutation.

For anchors `a < b`:

```text
maximize: n = (x - a) / (b - a)
minimize: n = (b - x) / (b - a)
index:    q = sum(weight_i * n_i)
```

All arithmetic uses the repository's bounded 34-digit Decimal context. Weights
must be positive and sum exactly to `1`. Adding or removing a candidate does
not renormalize other candidates.

Values or component bounds outside `[a, b]` are not clamped. The affected
candidate receives `out_of_reference` and is rejected from the scalar index.
Missing and quarantined signals also reject that candidate. All two to four
policy components are required: there is no available-case averaging,
imputation, zero fill, or weight redistribution.

The component evaluations retain their original bounds and sample counts. The
v1alpha1 composite intentionally publishes neither lower/upper bounds nor a
sample count: heterogeneous benchmark confidence intervals, hard ranges,
repeated-run dispersion, and task counts do not have a valid generic aggregate
interpretation. Per-component fields remain available in the snapshot and
catalog metadata.

## Correlation and the two-to-four claim

The implementation enforces exactly two to four policy components and requires
all of them for a score. It also rejects reuse of the same semantic source,
normalization reference, benchmark workload, or raw artifact across different
correlation groups.

That is not proof that two differently packaged benchmarks are statistically
independent or free of task overlap. Correlation groups are disclosure, not a
statistical model, and every artifact states
`statistical_independence_assumed: false`. Operators remain responsible for
task-set overlap, contamination, evaluator bias, and whether the weights model
the declared composite workload.

## Catalog provenance and publication rights

Only fully scored candidates receive the derived quality observation. Rejected
candidates remain in an enriched base catalog without that signal so the
ordinary frontier engine rejects them visibly.

The synthetic observation source is deliberately fail-closed:

- `license` is `NOASSERTION`;
- `raw_sha256` is the exact oracle snapshot ID;
- `retrieved_at` is oracle generation time;
- methodology records snapshot expiry and the need for component-level review.

Catalog metadata retains every complete component source and explicit rights
fields, along with all semantic, raw, retrieval, rights, capture, normalization,
projection, frontier, catalog, and bundle hashes. Every derived catalog remains
`publication_safe: false`; neither a license allowlist nor an authorized source
ID can make it public. Publication requires a separate reviewed projection that
independently confirms every component's permission, license, terms, and safe
output fields. The oracle grants no redistribution rights.

Pair the verified quality signal with a separately sourced cost or performance
metric in an ordinary frontier definition. Pricing changes invalidate that
cost catalog/frontier and its downstream selection. The already bound quality
bundle and verified quality-oracle snapshot remain independently valid until
their own expiry. If an operator deliberately rebuilds a two-axis benchmark
component with the new companion price, its exact frontier and bundle pins also
change, but the selected-quality projection remains stable. Repricing does not
manufacture a quality change.

## CLI replay workflow

After building and verifying the two-to-four-component quality bundle, create
the opt-in scalar artifact at a trusted time:

```console
modelskyline build-quality-oracle quality-oracle-policy.json \
  quality-bundle.json --as-of 2026-08-31T23:00:00Z \
  --output quality-oracle.json

modelskyline verify-quality-oracle quality-oracle-policy.json \
  quality-bundle.json quality-oracle.json \
  --at 2026-08-31T23:01:00Z
```

Enrichment deliberately requires the policy and bundle again; the oracle
snapshot is not standalone routing authority:

```console
modelskyline enrich-catalog-with-quality-oracle \
  cache-aware-cost-catalog.json quality-oracle-policy.json \
  quality-bundle.json quality-oracle.json \
  --at 2026-08-31T23:01:00Z \
  --output cost-and-quality-catalog.json
```

These three derivation commands write private files with mode `0600` on POSIX
and refuse to replace an existing path unless `--overwrite` is supplied:
`build-quality-bundle`, `build-quality-oracle`, and
`enrich-catalog-with-quality-oracle`.

The input catalog must have the exact composite workload and exact complete
candidate universe carried by the oracle. A changed provider, model revision,
endpoint, billing mode, region, tier, quantization, effort, harness, capability
set, or even reused `offering_id` fails closed.
