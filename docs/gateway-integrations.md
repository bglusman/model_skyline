# Runtime and gateway integrations

ModelSkyline is the selection control plane. An agent runtime, SDK adapter, or
gateway is the execution data plane. Version 0.9 integrates them through the
ordinary `SelectionSnapshot` JSON artifact; it does not ship a gateway server
or a signed remote-distribution protocol.

## Minimal consumer contract

A consumer does not need to embed Python. Its useful boundary is:

```text
trusted SelectionSnapshot bytes
  -> structural and semantic validation
  -> exact local OfferingKey bindings
  -> expiry and expected-policy checks
  -> one selection pinned for a complete work unit
  -> ordered, locally bounded attempts
  -> content-free receipt/telemetry
```

The consumer should:

1. Load the artifact from a trusted regular local file or authenticated HTTPS
   origin with bounded size and time. A custom loader owns equivalent checks.
2. Validate the committed selection schema, snapshot hash, policy/frontier
   binding, generation time, and `valid_until`. Pin expected project/selection
   identity when the deployment has that context.
3. Map each complete `OfferingKey` to an operator-created local target. Remote
   fields must never construct an endpoint, credential, provider header,
   command, or catch-all route.
4. Admit a work unit once and retain its ordered target tuple for every turn,
   tool call, retry, and subagent covered by that unit. A later selection is for
   newly admitted work only.
5. Intersect the pinned tuple with capabilities and health. It may skip an
   unavailable member without reordering the rest. An empty set fails closed;
   it does not widen to a similarly named model.
6. Apply one global attempt/time budget and stop fallback after response bytes
   or a non-idempotent side effect crosses the boundary.

`DynamicResolver` supplies bounded file/HTTP loading, ordinary-selection
validation, and a process-local last-known-good value. The consumer still owns
complete-key target mapping and work-unit pinning. It is a convenience for a
trusted channel, not an authentication or durable coordination protocol.

## Wardwright phase 0

[Wardwright](https://github.com/bglusman/wardwright) is the first native
consumer target because it can place selection behind an OpenAI-compatible
logical model while keeping ModelSkyline out of the request path.

The deliberately small phase-0 profile is:

- read one ordinary `SelectionSnapshot` from a trusted local regular file;
- validate its hash, time bounds, and configured identity expectations;
- map complete `OfferingKey` values to explicit Wardwright target IDs;
- pin the resolved default/fallback tuple once per run/work unit; and
- fail closed for a new run when the current local artifact cannot be admitted.

This is enough to demonstrate that a real runtime can consume the same artifact
produced by `modelskyline select` without knowing the frontier calculation. It
does **not** claim signed remote distribution, restart-safe rollback protection,
automatic configuration mutation, provider-error fallback execution, or
Responses API/session affinity. Those are later phases only if the local-file
experiment proves useful.

An integration fixture should be generated by ModelSkyline, checked into the
Wardwright test suite with provenance, and exercised with two local fake target
bindings. The critical test is: work unit A pins generation 10, generation 11
becomes current for new work unit B, and A remains on generation 10 for its full
trajectory. Unknown mappings, expiry, same `offering_id` with a changed complete
key, symlinks/FIFOs, and partial writes must fail before provider execution.

Later Wardwright work can separate stable target ID, immutable local target
revision, and upstream provider model; persist generations and work-unit pins;
execute typed ordered fallback; and emit bounded trace records. That work should
remain in Wardwright rather than turning ModelSkyline into a gateway.

## Other integration points

The same ordinary-selection boundary can attach to several systems:

| System | Practical first integration | Important constraint |
| --- | --- | --- |
| [LiteLLM](https://docs.litellm.ai/docs/proxy/model_management) | The [experimental separate controller](../integrations/litellm/README.md) stages one immutable versioned model group, verifies it, then flips one stable alias | This is a version-pinned blue/green cutover with a single-writer requirement, not a documented cross-resource transaction. Retain old groups through the work-unit TTL; LiteLLM session affinity pins a deployment, not a ModelSkyline generation. See [the integration design issue](https://github.com/bglusman/model_skyline/issues/17). |
| [vLLM](https://docs.vllm.ai/en/latest/serving/openai_compatible_server/) / [Production Stack](https://docs.vllm.ai/projects/production-stack/) | Inference serving and replica/cache-routing beneath one exact selected offering | vLLM is not an equivalent cross-model selection control plane: startup aliases and same-model replica failover do not provide ordered cross-model/cross-provider selection or snapshot-generation pinning; put a consumer or gateway controller above it. |
| [Envoy AI Gateway](https://github.com/envoyproxy/ai-gateway) | Controller maps selected offerings to pre-existing backend references and priority | Reconcile only operator-created backends; preserve generation/work-unit affinity outside ordinary retry configuration. |
| [Gateway API Inference Extension](https://gateway-api-inference-extension.sigs.k8s.io/) | Serving tier beneath one selected offering | An `InferencePool` may choose a replica of an offering, not another frontier model. |
| [Vercel AI SDK](https://ai-sdk.dev/docs/ai-sdk-core/provider-management) | Custom provider exposes a stable logical model whose object owns the pinned selection | Pin before `doGenerate`/`doStream`; a fallback provider or late middleware must not widen the list. |
| [Bifrost](https://github.com/maximhq/bifrost) | Pre-request selection paired with a blocking fail-closed hook | A non-blocking plugin error is not a policy gate; selection must happen once, before attempts. |
| [OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection) | Hosted executor for one exact model/provider endpoint per local attempt | Disable hosted fallback and broad provider matching when endpoint, region, or tier is part of `OfferingKey`. |
| LangChain, Pydantic AI, OpenAI Agents SDK | Thin model/provider adapter when no central gateway exists | Propagate a work-unit lease explicitly and prevent nested SDK retries from multiplying the published budget. |

The first contribution for any ecosystem should be a read-only consumer and
fake-provider integration test. A controller that mutates production routes,
credentials, or remote infrastructure needs separate review and should not be
implied by schema parsing alone.

## OpenAI-compatible endpoints

An OpenAI-compatible Chat Completions or Responses endpoint can hide target
changes from an agent behind a stable logical model name. That is data-plane
compatibility, not selection correctness. A model string and generic retry
configuration do not convey complete offering identity, expiry, work-unit
pinning, or exact fallback order.

Resolve and pin the `SelectionSnapshot` in trusted local code before serving the
request. Keep generation/lease metadata on an authenticated internal hop, strip
it before provider execution, and never let a public client header select a
local target revision directly.

## Attempts, receipts, and feedback

Selection declares an ordered candidate list; it does not execute retry or
fallback. The runtime owns:

- typed local health and capability skips;
- provider failures and which are retryable;
- one total attempt/deadline budget across SDK, proxy, and provider layers;
- stream and side-effect cutoffs; and
- pin retention across turns, tools, and subagents.

At admission, retain only bounded identifiers: selection/policy/frontier hash,
workload, chosen offering digest, fallback index, generation/expiry, and whether
a bounded last-known-good value was used. Project runtime feedback into the
versioned `RequestTrace` contract while preserving whether a row is one provider
request, hidden-retry model call, attempt aggregate, or work-unit aggregate.

Do not record prompts, tool content, credentials, endpoint URLs, repository
paths, tenant email, or raw session/work-unit IDs. Pseudonymize correlations
with a domain-separated rotating-key HMAC and keep telemetry delivery
asynchronous.

## Trust and deferred signed distribution

A content hash proves that bytes match an expected identity; it does not prove
who published them. HTTPS authenticates a configured origin only to the extent
of the deployment's TLS and origin controls. Local-file delivery relies on host
filesystem permissions and deployment discipline. `DynamicResolver` rollback
and last-known-good state are process-local.

The former DSSE pointer, threshold-key policy, SQLite store, portable vectors,
and signed gateway resolver were removed from the v0.9 shipped surface because
they had no demonstrated consumer and materially duplicated the simple
selection path. [ADR 0003](adr/0003-signed-gateway-selection-protocol.md)
preserves that design as historical research, not a current protocol or
security claim.

If untrusted distribution becomes a demonstrated requirement, a future design
must cover publisher identity, audience/channel binding, exact artifact bytes,
hard expiry, durable rollback/equivocation state, key rotation, target-revision
binding, and cross-language conformance. It should be rebuilt around a concrete
native consumer rather than restored speculatively.

## Claiming an integration

Before documenting an integration as usable, test at least:

- a real ModelSkyline-produced ordinary selection artifact;
- exact complete-key mappings to two fake local targets;
- default and ordered fallback resolution;
- selection rotation while an existing work unit remains pinned;
- expiry, future time, malformed/hash-invalid input, unknown mapping, partial
  write, symlink, FIFO, and oversized-file rejection; and
- no provider invocation after a policy failure.

State transport, durability, retry, and restart limitations explicitly. Passing
JSON Schema alone is not evidence of correct semantic validation or runtime
pinning.
